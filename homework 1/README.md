## Как проверить объявление

Отправляем POST на `/predict` с JSON. Например, так:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{
    "seller_id": 1,
    "is_verified_seller": false,
    "item_id": 10,
    "name": "Велосипед",
    "description": "Городской велосипед в хорошем состоянии",
    "category": 2,
    "images_qty": 0
  }'
```

Здесь в ответ придёт `true`: продавец не подтверждён и фотографий нет.
Если поставить `images_qty` больше нуля или `is_verified_seller: true`,
получим `false`. То есть `true` — нарушение есть, `false` — всё нормально.
При успешной проверке статус всегда `200`, а в теле только булево значение.

Все семь полей обязательны. `seller_id`, `item_id` и `category` должны быть
целыми числами больше нуля, `images_qty` — целым числом от нуля.
`is_verified_seller` принимает только boolean, а `name` и `description` — строки,
которые не состоят из одних пробелов. Лишние поля тоже не принимаются.
Типы не приводятся автоматически: например, строка `"1"` вместо числа не пройдёт.

Если с запросом что-то не так, вернётся `400` с ошибками в `detail`.
Если сломается сама обработка — `500` и `{"detail": "Internal server error"}`,
а подробности останутся в логе.

Код разделён на обработчик (`routers`), логику проверки (`services`)
и хранение результатов (`repositories`). Модели входных данных лежат в `schemas.py`,
зависимости собираются в `dependencies.py`, приложение — в `main.py`.
Базы данных пока нет: последний результат для каждого объявления хранится в памяти
и теряется после перезапуска. При новом запросе объявление проверяется заново.

## Тесты

В том же окружении ставим зависимости для тестов и запускаем pytest:

```bash
pip install -r requirements-dev.txt
python -m pytest
```

В тестах есть разные сочетания подтверждения продавца и количества картинок,
пропущенные поля, неправильные типы и значения, сломанный JSON.
Отдельно проверяется, что ошибки в сервисе и репозитории превращаются в `500`.
